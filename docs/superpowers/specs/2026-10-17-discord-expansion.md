# Discord Channel Capabilities Expansion Spec

**Date:** 2026-10-17  
**Status:** Draft  
**Scope:** `backend/src/interface/channels/discord/` (`commands.rs`, `render.rs`, `outbound.rs`, `inbound.rs`, `gateway.rs`, `worker.rs`, `mod.rs`)

---

## 1. Intent and Why

The Discord channel adapter currently implements the basic BotModule contract via single-string slash commands (`/todo args:"..."`), text-only DM conversations, and embeds without buttons.

Track 2 item 3 of `docs/superpowers/HANDOFF.md` specifies expanding Discord channel capabilities in three key areas:
1. **Interactive ActionRow Buttons:** When BotModules return replies with `content.actions` (such as the "Done #id" buttons generated by the todo module), Discord renders interactive `ActionRow` buttons. When a user clicks a button, Discord fires a `ComponentInteraction`, which the bot handles and dispatches as if the user typed the command, immediately acknowledging and updating the message.
2. **Typed Slash Command Options:** In addition to the existing single-string `args` option fast-path, provide structured subcommands/options for `/todo` (`add task:String`, `done id:Integer`, `list`) and `/expense` (`add amount:String note:String`, `list`) to make Discord autocompletion and mobile typing intuitive.
3. **Inbound Receipt/Image Attachment Ingestion Over DMs:** When a user uploads a receipt photo in a direct message with the bot, download the attachment, store it in `StorageService` under `StorageCategory::Receipts`, enqueue the durable `media.process_receipt` job, and send an immediate confirmation notice back to the DM.

---

## 2. Goals, Non-Goals, and Anti-Goals

### Goals
- **Interactive ActionRows:** Map `content.actions` to Discord ActionRow buttons (up to 5 buttons per row, up to 5 rows per message).
- **Component Interaction Handling:** Handle `Interaction::Component` in gateway, acknowledge within Discord's 3-second deadline, route through the shared worker queue and inbound pipeline, and edit/reply with the outcome.
- **Typed Slash Options with Fallback:** Support both structured subcommands (`/todo add`, `/todo done`, `/todo list`, `/expense add`) and legacy single-string fallback (`args`).
- **DM Receipt Ingestion:** Download image attachments in DMs, persist to `StorageCategory::Receipts`, enqueue `media.process_receipt`, and reply with acknowledgment.
- **Fail-Closed Security & Permissions:** DM only for receipts; unlinked senders receive `UNLINKED_REPLY` prompting to link; no guild message attachments processed.

### Non-Goals
- Supporting non-image media uploads over Discord (audio voice notes on Discord remain output-only).
- Adding Discord modal text-input popups (ActionRow buttons and slash commands suffice).
- Altering shared domain or application logic: all actions dispatch through `Inbound::handle` or standard services.

### Anti-Goals
- Never block serenity gateway event handlers with synchronous I/O or unbounded downloads.
- Never drop backward compatibility with the single-string slash command format (`/todo args:"..."`).
- Never panic on malformed custom IDs, unknown component interactions, or oversized image attachments.

## 3. Architecture & Mechanics

### 3.1 Interactive ActionRow Buttons

#### 3.1.1 Rendering (`render.rs` & `outbound.rs`)
In `render.rs`:
```rust
pub struct Post {
    pub description: Option<String>,
    pub files: Vec<Attachment>,
    pub buttons: Vec<(String, String)>, // (label, custom_id)
}
```
When `posts(content: &Content)` runs:
- If `!content.actions.is_empty()`, map up to 25 actions (capped at Discord's 5x5 button limit, matching Telegram's `MAX_BUTTONS` policy) to `buttons` on the last post.
- Action label truncated at 80 characters, custom_id capped at 100 bytes.
- In `outbound.rs`, partition `post.buttons` into chunks of 5 and construct `CreateActionRow::Buttons(...)` containing `CreateButton::new(custom_id).label(label).style(ButtonStyle::Secondary)`.
- Attach components to `CreateMessage`, `EditInteractionResponse`, and `CreateInteractionResponseFollowup`.

#### 3.1.2 Inbound Component Handling (`inbound.rs`, `gateway.rs`, `worker.rs`)
- In `inbound.rs`:
  ```rust
  pub fn from_component(interaction: &ComponentInteraction) -> Result<Parsed, CommandRefusal>
  ```
  Parses `interaction.data.custom_id` into `InboundText::Command`.
- In `gateway.rs`:
  Match `Interaction::Component(component)`:
  - Defer update or defer response according to guild ephemerality.
  - Enqueue `Work::Component { interaction, parsed, mode }`.
- In `worker.rs`:
  - Worker passes `parsed` through `inbound.handle`.
  - Delivers outcome by editing the component interaction response.

### 3.2 Typed Slash Command Options (`commands.rs`)

#### 3.2.1 Command Builders
Update `create_commands()`:
- `/todo`:
  - Subcommand `add` with option `task` (String, required).
  - Subcommand `done` with option `id` (Integer, required).
  - Subcommand `list` with no required options.
  - Option `args` (String, optional) as the fallback single-string input.
- `/expense`:
  - Subcommand `add` with option `amount` (String, required) and option `note` (String, required).
  - Subcommand `list` with no options.
  - Option `args` (String, optional) as the fallback.
- `/ask`, `/portfolio`, `/link`, `/help` remain unchanged.

#### 3.2.2 Inbound Command Parser
In `inbound.rs`:
- Check `interaction.data.options`:
  - If a `CommandDataOptionValue::SubCommand(sub_opts)` is present:
    - Build normalized command and args (e.g. `todo add milk`, `todo done 3`, `expense add 15.50 lunch`).
  - Else check for `args` or `prompt` string options.

---

### 3.3 DM Receipt Image Ingestion (`inbound.rs`, `gateway.rs`, `worker.rs`)

- In `gateway.rs`:
  In `async fn message(&self, ctx: Context, message: Message)`:
  - If `message.guild_id.is_none()` and `!message.author.bot`:
    - If `!message.attachments.is_empty()` and any attachment is an image (`image/*` or valid image extension):
      - Enqueue `Work::DirectAttachment { channel, message_id, author, attachment, caption }`.
- In `worker.rs`:
  - Resolve sender identity via `inbound`.
  - If unlinked, reply with `UNLINKED_REPLY`.
  - If linked (`owner_id`):
    - Download image bytes from Discord CDN (bounded by timeout, max 10 MiB).
    - Save to `StorageService` with `StorageCategory::Receipts`.
    - Enqueue `media.process_receipt` job with `ConversationAddress::Discord(channel_id)`.
    - Send confirmation reply: `🧾 Receipt received and queued for processing!`.
