# Spec: Finance budgets

**Status:** draft for approval, 2026-10-18. Next: implementation plan in `docs/superpowers/plans/`.

## 1. Problem

The ledger records what happened (`domain/finance::Transaction`) and analytics explain it after the fact (`finance_analytics`, `finance::audit`), but nothing says *how much I meant to spend*. There is no way to set "€300 a month on food", see how much of it is left mid-month, or be told before the month is blown. Every surface (chat, web, AI) can only answer "what did I spend", never "am I on track".

## 2. Goals and non-goals

**Goals**

- A **monthly spending limit** per category, plus an optional **overall** monthly limit, each in one currency.
- A **status view** for any month: limit, spent, remaining, percent used, pace against the calendar, projected month-end spend.
- **Alerts** when spending in the current month crosses 80 % and 100 % of a limit, sent once per budget, month and threshold.
- Inline feedback: logging an expense in chat that lands a budget at ≥ 80 % says so in the same reply.
- The same capability from chat, REST, AI tools/MCP, the web UI and the daily briefing.

**Non-goals (YAGNI)**

Weekly, yearly or custom periods; rollover of unspent amounts; envelope/zero-based budgeting; income targets or savings goals; budgets that combine currencies (no FX conversion — currencies are never summed without a rate, as everywhere else in finance); per-budget custom thresholds; budget history/versioning (a changed limit applies to every month it is viewed for); alerts for past months.

**Anti-goals**

- An alert that fires twice for the same crossing, or fires for a backdated entry in an old month.
- A budget amount stored or compared as floating point.
- A transaction write that fails because alert evaluation failed for a reason unrelated to the write (see §5.3: evaluation shares the transaction, so it must only fail on real database errors).

## 3. Decisions

All decisions below are the author's calls (the owner asked for a proposal, not a Q&A).

| Decision | Choice | Why |
|---|---|---|
| Period | Calendar month in the owner's timezone (`settings.tz()`) | Matches `!expense summary` ("this month") and how people think about budgets |
| Scope | One category, or overall (`category_id NULL`) | Covers "food" and "everything"; tag- or room-scoped budgets have no current need |
| What counts | Expense transactions only, in the budget's currency, `occurred_at` inside the month; includes rows generated by recurring bills and portfolio cash | A bill paid is money spent; excluding sources would make the number disagree with the ledger |
| Uncategorised spending | Counts toward the overall budget only | It has no category to match |
| Uniqueness | One budget per (owner, category-or-overall, currency) | Two limits for the same thing has no meaning |
| Category deleted | Its budgets are deleted with it (`ON DELETE CASCADE`) | A budget for a category that no longer exists cannot be evaluated; transactions are already left uncategorised by the delete |
| Thresholds | Fixed 80 % and 100 % | One warning, one breach; configurable thresholds wait for a request |
| Alert idempotency | Row in `finance_budget_alerts` keyed (budget, month, threshold), inserted `ON CONFLICT DO NOTHING`; only the inserting transaction enqueues delivery | Concurrent expenses, retried AI calls and edits can never send a crossing twice |
| Alert after a dip | Not re-sent: once a threshold was crossed in a month it stays recorded, even if an edit drops spending below it and a later expense raises it again | Simpler, and a repeat for the same month is noise |
| Alert delivery | New job `BudgetAlertSend`, enqueued in the same transaction; its handler DMs every linked identity on a connected channel, exactly like `PortfolioCheckAlerts` | Reuses the proven delivery path; a crash after commit still delivers |
| Pace | `expected = limit × elapsed_days / days_in_month`; `projected = spent × days_in_month / elapsed_days` (integer minor units, rounded toward zero); only for the current month | Simple, explainable; elapsed days count today as elapsed |
| Money | `limit_minor BIGINT > 0` with `currency` + `currency_exponent`, as on `transactions` | Same invariants as the ledger; `money::parse_amount` / `exponent_for` reused |

## 4. Data model

### 4.1 Migration `backend/migrations/NNNN_finance_budgets.sql`

`NNNN` is the next free number at implementation time (`0012` is taken by the todo tags/recurrence/steps plan, so expect `0013`). Plain DDL, no data rewrite.

```sql
CREATE TABLE finance_budgets (
    id                BIGSERIAL PRIMARY KEY,
    owner_id          UUID    NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
    category_id       BIGINT  REFERENCES finance_categories(id) ON DELETE CASCADE,
    currency          TEXT    NOT NULL,
    currency_exponent BIGINT  NOT NULL,
    limit_minor       BIGINT  NOT NULL CHECK (limit_minor > 0),
    alerts_enabled    BOOLEAN NOT NULL DEFAULT TRUE,
    created_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- One budget per scope and currency; NULL (overall) is a value here.
CREATE UNIQUE INDEX idx_finance_budgets_scope
    ON finance_budgets (owner_id, category_id, currency) NULLS NOT DISTINCT;

CREATE TABLE finance_budget_alerts (
    budget_id   BIGINT   NOT NULL REFERENCES finance_budgets(id) ON DELETE CASCADE,
    month_start DATE     NOT NULL,          -- first day of the month in the owner's zone
    threshold   SMALLINT NOT NULL CHECK (threshold IN (80, 100)),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (budget_id, month_start, threshold)
);
```

- `finance_budgets` goes into `OWNED_TABLES` (`domain/accounts/mod.rs`). `finance_budget_alerts` has no owner column; it follows its budget.
- Account merge: `merge.rs` already remaps `transactions.category_id` from `from`'s colliding categories (matched on `LOWER(name)`) to `into`'s before deleting `from`'s duplicates. Budgets need the same step **before** that delete, or the cascade silently drops them: first delete `from`'s budgets whose remapped scope + currency already exists on `into` (including overall budgets), then remap the remaining budgets' `category_id`, then let `move_rows` move them. The surviving account's budget wins a collision. Test it next to the existing category-merge tests. *(Author's call.)*
- `.sqlx/` is regenerated and committed.

### 4.2 Domain `domain/finance/budget.rs` (new)

Pure, synchronous, unit-tested in the file.

- `BudgetScope { Overall, Category { id: i64, name: String } }`.
- `Budget { id, owner_id, scope, currency, currency_exponent, limit_minor, alerts_enabled, created_at, updated_at }`.
- `NewBudget` / `BudgetPatch` (limit, alerts flag); validation: `limit_minor > 0`, currency normalised by `money::normalise_currency`, exponent from `money::exponent_for`. Changing a budget's scope or currency is not a patch: remove and re-add.
- `Threshold { Warning = 80, Exceeded = 100 }`.
- `reached_thresholds(spent_minor, limit_minor) -> Vec<Threshold>` — integer comparison `spent × 100 ≥ limit × pct` (use `i128` to avoid overflow).
- `Month` value: `Month::containing(instant, tz)`, `start_utc()`, `end_utc()` (exclusive), `days()`, `parse("YYYY-MM")`. DST-correct because bounds are computed as local midnights converted to UTC.
- `BudgetStatus { budget, month, spent_minor, remaining_minor (may be negative), percent_used (integer, floor), state: Ok | Warning | Exceeded, pace: Option<Pace> }`, `Pace { expected_minor, projected_minor }` — built by `status(budget, spent, month, now, tz)`; `pace` is `None` unless `month` contains `now`.
- `FinanceError` gains `BudgetExists`, `BudgetNotFound`, `BudgetLimitInvalid` (mapped to `AppError::Validation` / `NotFound` as the existing variants are).

## 5. Service behaviour (`application/finance/budgets.rs`, on `FinanceService`)

### 5.1 Budget CRUD

`create_budget`, `update_budget`, `delete_budget`, `list_budgets(owner)`. Each mutation is one transaction that writes and publishes `BudgetCreated` / `BudgetUpdated` / `BudgetDeleted { id, owner_id }` via `outbox::publish`. Category scope is resolved with the existing `resolve_category_in_tx` *without* creating a missing category (an unknown name is `UnknownCategory`). Duplicate scope → `BudgetExists`. Another owner's budget → `BudgetNotFound`.

A category delete that cascades its budgets publishes only the existing `CategoryDeleted`; the web view refetches budgets on that event as well. *(Author's call: no synthetic `BudgetDeleted` per cascaded row.)*

### 5.2 Status

`budget_status(owner, month: Option<Month>) -> Vec<BudgetStatus>`: month defaults to the owner's current month. One repository query sums expenses per (category, currency) in the month's UTC bounds, plus per currency for overall budgets; the domain builds each status. Ordered: overall first, then by percent used descending.

### 5.3 Evaluation on every expense write

A new `evaluate_budgets_in_tx(tx, owner, affected)` runs inside the same transaction as the ledger write, called from:

- `create_transaction_in_tx` (covers chat, REST, AI, receipt OCR, recurring bills and portfolio cash — they all go through it);
- `update_transaction` (evaluates the row's **new** values; lowering spend sends nothing).

Delete never evaluates.

Steps:

1. Return immediately unless the written row is an expense whose `occurred_at` falls in the owner's **current** month (backdated entries never alert).
2. Load the owner's budgets matching the row's currency and either its category or overall, `alerts_enabled = true`.
3. For each, sum the month's spend (within the transaction, so it includes this write) and compute `reached_thresholds`.
4. For each reached threshold, `INSERT … ON CONFLICT DO NOTHING RETURNING` into `finance_budget_alerts`. For each row actually inserted: publish `BudgetThresholdCrossed { owner_id, budget_id, threshold, month, spent_minor, limit_minor, currency, currency_exponent, scope_name }` and enqueue one `BudgetAlertSend` job (dedupe key `budget:{id}:{month}:{threshold}`).

If both 80 % and 100 % are reached by one write, only the 100 % alert is enqueued; both rows are recorded so 80 % never fires later that month.

The method returns the `BudgetStatus` of every budget it evaluated whose state is not `Ok`, so callers can show inline feedback without a second query.

**Guarantees**

| Scenario | Result |
|---|---|
| Two concurrent expenses both cross 80 % | Primary key serialises; exactly one inserter, one alert |
| Retried AI `record_finance_entry` | Second insert is a duplicate transaction (existing behaviour) but the alert row already exists; no second alert |
| Outbox publish or job enqueue fails | Whole transaction rolls back, including the expense; the caller sees the error as today |
| Expense backdated into last month pushes it over | Status for that month shows Exceeded; no alert |
| Edit lowers then a new expense re-crosses | No second alert this month |
| Budget limit raised after an alert | Already-recorded thresholds stay; crossing the new 100 % later in the month does not re-alert *(accepted cost of the simple rule)* |

### 5.4 Alert delivery job (`interface/jobs/budgets.rs`)

`BudgetAlertSend` handler: payload `{ owner_id, budget_id, month, threshold }`. Reloads the budget and the month's status (so the message shows current numbers); if the budget was deleted, completes silently. DMs every linked identity on a configured, connected channel, mirroring `CheckAlertsHandler` (defer while nothing is connected, one failed send does not stop the others). Message, escaped with `html_escape()`:

> **Budget warning:** Food — €246.00 of €300.00 used (82 %) with 12 days left.
> **Budget exceeded:** Overall — €1,530.00 of €1,500.00 (102 %).

Add `JobType::BudgetAlertSend` to `JobType::ALL` and the worker registry.

### 5.5 Briefing

`application/briefing/generator.rs` adds budgets in state Warning/Exceeded for the current month to the briefing model; the renderer lists them in one line each. Nothing is shown when all budgets are Ok or none exist.

## 6. Interfaces

All call the `FinanceService` methods above; none re-derives a rule.

### 6.1 Chat (`interface/chat/finance/budget.rs`, registered in `FinanceModule`)

Inputs capped at 500 characters; replies via `text_html` with every user value through `html_escape()`; amounts parsed with the existing `parse_entry`-style helpers and the owner's default currency.

| Command | Behaviour |
|---|---|
| `!budget` | Current month status: one line per budget, `Food  €246.00 / €300.00  82 %  ⚠`, plus pace for the current month |
| `!budget <YYYY-MM>` | Status for that month (no pace) |
| `!budget set <amount> [CUR] [category]` | Create or update (same scope+currency → update the limit). No category = overall. Unknown category → error naming `!category add` |
| `!budget rm [category] [CUR]` | Remove; `CUR` needed only when the scope has budgets in more than one currency |
| `!budget alerts <on\|off> [category] [CUR]` | Toggle alerts for one budget |

`!expense add` replies gain one line per non-Ok budget returned by evaluation, e.g. `Food budget: 85 % of €300.00 used`. Help entries are added to `FinanceModule::commands()`. Keep `handler.rs` under 500 production lines by putting all budget parsing/formatting in `budget.rs`.

### 6.2 REST (`interface/http/finance_budgets.rs`)

- `GET /api/v1/finance/budgets?month=YYYY-MM` → `BudgetStatus[]` (month optional).
- `POST /api/v1/finance/budgets` `{ category_id?: number, currency: string, limit: string, alerts_enabled?: boolean }` (limit as a decimal string, as transaction amounts are).
- `PUT /api/v1/finance/budgets/{id}` `{ limit?: string, alerts_enabled?: boolean }`.
- `DELETE /api/v1/finance/budgets/{id}`.
- Transaction create/update responses are unchanged (inline feedback is chat-only; the web refetches status on events).
- Errors through `ApiError`; another owner's budget → 404; duplicate → 409. No step-up routes. Register in `routes_finance()`.
- Additive OpenAPI change: regenerate `backend/openapi.json` and the frontend client; add a `contracts/` fixture for `BudgetStatus` if finance DTOs have fixtures.

### 6.3 AI tools and MCP (`llm/tools/finance.rs`, or a new `llm/tools/budgets.rs` if `finance.rs` would pass 500 lines)

- `get_budget_status { month?: "YYYY-MM" }`.
- `set_budget { amount: string, currency?: string, category?: string, alerts_enabled?: boolean }`.
- `remove_budget { category?: string, currency?: string }`.
- `record_finance_entry` result includes any non-Ok budget statuses from evaluation, so the model can mention them.

OpenAI `type: "function"` schemas; arguments validated like any input; owner only from the authenticated context. MCP exposes the same registry.

### 6.4 Web (`frontend/src/modules/finance/`)

- New `components/BudgetPanel.tsx` in the ledger view above the transaction list: one row per budget with name (Geist Sans), amounts (Geist Mono), a progress bar, percent and state text ("On track", "82 % used", "Over by €30.00"), and for the current month a pace marker on the bar. State is conveyed by text, not colour alone (Design.md).
- Month selector (previous/next) shared with the panel.
- `components/BudgetModal.tsx` to add/edit: scope select (Overall + categories), currency (defaults to settings), limit, alerts toggle; remove button with confirmation. `Escape` closes, `Enter` submits.
- Refetch on `TransactionCreated/Updated/Deleted`, `Budget*`, `BudgetThresholdCrossed` and `CategoryDeleted` SSE events.
- Mock routes in `frontend/e2e/fake-api.ts`; Playwright coverage in `frontend/e2e/finance.spec.ts` (create budget, see progress, edit, remove).

## 7. Events

New `SystemEvent` variants, each with a meaningful `owner_id()` and `event_type()`: `BudgetCreated(Budget)`, `BudgetUpdated(Budget)`, `BudgetDeleted { id, owner_id }`, `BudgetThresholdCrossed { … }`. No durable destinations (`destinations()` unchanged); chat delivery goes through the job in §5.4.

## 8. Testing

| Level | Cases |
|---|---|
| Domain | `reached_thresholds` at 79/80/99/100/150 % and with values near `i64::MAX`; `Month` bounds in a DST-shifting zone and at year end; `status` remaining negative when over; pace only for the current month, first and last day; zero-decimal (`JPY`) and three-decimal (`KWD`) currencies; validation of limit ≤ 0 and bad currency |
| Repository | Round-trip; `NULLS NOT DISTINCT` refuses a second overall budget per currency; owner isolation; month spend sum excludes income, other currencies, other categories, and rows outside the bounds; cascade on category delete |
| Service | CRUD publishes events; crossing 80 % inserts one alert row, publishes `BudgetThresholdCrossed` and enqueues one job; one write crossing both thresholds enqueues only the 100 % job and records both; concurrent crossings → one alert; backdated expense → no alert; `alerts_enabled = false` → no alert; failed outbox publish rolls back the expense and the alert row; recurring-bill payment and portfolio cash flows trigger evaluation; overall budget counts uncategorised rows |
| Job | Sends to every connected linked identity; deferred while disconnected; deleted budget completes silently; message escapes category names |
| Chat / REST / AI | Command parsing (overall vs category, currency optional, unknown category); `!expense add` inline line; 404 on another owner's budget, 409 on duplicate; tool argument validation and malformed input |
| Merge | `finance_budgets` in `OWNED_TABLES`; colliding scopes resolved as in §4.1; schema catalog test passes |
| E2E | Playwright budget flow in the finance module |
