# Step 9: Transactional Outbox — Design

> Sub-project 1, design step 9. Binding parent: `2026-09-24-postgres-foundation-design.md` §5.2 (D9).
> Roadmap: `SPEC.md` §6. Approved by the user section by section on 2026-09-30.
> Branch: `refactor/outbox` (from `refactor/postgres-layered` at `65236b5`).

## 1. Goal

Every state change and the event describing it commit together in one PostgreSQL transaction.
Events reach the browser through `LISTEN`/`NOTIFY` instead of an in-process broadcast
channel. Durable destinations (a Matrix room today) are delivered from per-destination rows
that survive a restart and retry independently. The in-process `EventBroadcaster`, the
`webhook_outbox` table and the last user of the old background-worker mechanism are removed.

Out of scope:
- outgoing HTTP webhooks to third parties (none exist; `X-Delivery-Id` waits for the first one);
- chat notifications other than webhook alerts (reminders and briefings already run as jobs, step 8);
- Discord/Telegram destinations (sub-project 2);
- frontend changes (the SSE wire format is kept).

## 2. Current state

| Piece | Where | Behaviour |
|---|---|---|
| `SystemEvent` + `EventBroadcaster` | `backend/src/events.rs` (crate root) | `tokio::sync::broadcast`, capacity 100; `owner_id()` returns `String` |
| Publishing | ~99 sites in ~20 services, plus `interface/chat/briefing/handler.rs` (`!briefing now`) | `self.events.send(..)` **after** the write, usually on the bare pool with no transaction; a crash between the two loses the event |
| Consumers | `interface/http/sse.rs` only | every other `subscribe()` is a test asserting an event was emitted |
| Plumbing | `BotModule::handle_command(ctx, services, db, Option<&EventBroadcaster>)`, `interface/channels/matrix/{mod,handler,sync_loop,command_flow,attachments}.rs`, `ApiState.broadcaster`, `AppServices::with_events` | |
| Webhooks | `application/webhooks`, `interface/chat/webhooks.rs`, `interface/http/webhooks/` | **Inbound only**: an external system POSTs an alert, the bot posts it to a Matrix room. `webhook_outbox` queues the room message; a worker spawned by `BotModule::spawn_background_workers` drains it every 3 s or on a `Notify`; 10 attempts, `domain::webhooks::retry_delay`; updates `webhooks.total_delivered_count` / `failure_count` |
| Webhook logs | `GET /api/v1/account/webhooks/{id}/logs` → `WebhookOutboxItem` | reads `webhook_outbox`; the DTO is part of the frozen contract |
| Inbound response | `POST /api/v1/webhooks/{token}` → `InboundAcceptedResponse` | returns the `webhook_outbox.id` (`outbox_<uuid>`) |

## 3. Decisions

| # | Decision | Why |
|---|---|---|
| O1 | The outbox row is written **in the same transaction** as the state change, at every publish site (user decision) | SPEC NFR "No Phantom State"; closes the crash window |
| O2 | `webhook_outbox` history is **dropped**, not migrated (user decision) | Simplest; the logs start empty after cutover |
| O3 | Durable deliveries run on their **own dispatcher** over `outbox_deliveries`, not as jobs | D9 already chose per-destination delivery rows; a job per delivery would track every delivery twice |
| O4 | Claims use a **lease** (`available_at = now() + 60 s`) instead of a `running` status and a reaper | Crash recovery with no extra status or loop; SPEC's three statuses stay |
| O5 | `NOTIFY outbox` carries `<event id>:<account uuid>` from an `AFTER INSERT` trigger | Fires only on commit (R25 precedent); an instance with no SSE client for that account never reads the row |
| O6 | Retention is 30 days for finished events | SPEC §6.1; webhook logs therefore show the last 30 days |

## 4. Schema

### 4.1 `backend/migrations/0004_outbox.sql` (DDL only)

```sql
CREATE TABLE outbox_events (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    account_id  UUID NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
    event_type  TEXT NOT NULL,                 -- SystemEvent variant name
    payload     JSONB NOT NULL,                -- serialised SystemEvent ({type, payload})
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_outbox_events_account_type_created
    ON outbox_events (account_id, event_type, created_at DESC);
CREATE INDEX idx_outbox_events_created ON outbox_events (created_at);

CREATE TABLE outbox_deliveries (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    event_id      BIGINT NOT NULL REFERENCES outbox_events(id) ON DELETE CASCADE,
    destination   TEXT NOT NULL,               -- 'matrix:<room id>'
    status        TEXT NOT NULL DEFAULT 'pending'
                  CHECK (status IN ('pending', 'delivered', 'failed')),
    attempts      INTEGER NOT NULL DEFAULT 0,
    max_attempts  INTEGER NOT NULL DEFAULT 10,
    available_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    delivered_at  TIMESTAMPTZ,
    last_error    TEXT,
    CONSTRAINT uq_outbox_delivery UNIQUE (event_id, destination)
);

CREATE INDEX idx_outbox_deliveries_pending
    ON outbox_deliveries (available_at) WHERE status = 'pending';

CREATE FUNCTION outbox_notify() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
    PERFORM pg_notify('outbox', NEW.id::text || ':' || NEW.account_id::text);
    RETURN NULL;
END $$;

CREATE TRIGGER outbox_events_notify AFTER INSERT ON outbox_events
    FOR EACH ROW EXECUTE FUNCTION outbox_notify();
```

- `max_attempts` defaults to **10**, not SPEC's 8: today's webhook delivery makes 10 attempts (behaviour frozen).
- `outbox_events` is classified `ACCOUNT_ID_FOLLOWS` (like `jobs`, R23), so an account merge moves it. The catalog test's UUID-and-FK check covers the new column.
- Delivery rows need no owner column; they follow their event.

### 4.2 `backend/migrations/0005_drop_webhook_outbox.sql`

`DROP TABLE webhook_outbox;` (its index goes with it). It is a separate migration so that 0004 can land before
webhooks switch over and every commit stays green; committed migrations are never edited.

## 5. Components

### 5.1 `domain/events.rs`

`SystemEvent` moves here from `backend/src/events.rs`. It stays a serde-tagged enum
(`#[serde(tag = "type", content = "payload")]`) with **unchanged variant names**: the SSE wire format is a published contract.

- Every `owner_id: String` field becomes `owner_id: AccountId`. It serialises to the same `acct_<32 hex>` string, so the wire format is unchanged. `owner_id()` returns `&AccountId`, and an outbox row can never carry a malformed account.
- `fn event_type(&self) -> &'static str`: the variant name, pinned against the serde tag by a test.
- `fn destinations(&self) -> Vec<Destination>`: pure. Today only `WebhookTriggered { room_id, .. } → Destination::MatrixRoom(room_id)`.
- `enum Destination { MatrixRoom(String) }` with `as_key()` → `matrix:<room>` and a `parse` inverse (a unit test round-trips them).
- `WebhookTriggered` gains `title: Option<String>`, `html_body: String`, `plain_body: String`, so the event is the single record of the alert. This is an additive SSE field change; the frontend ignores unknown fields. `outbox_id` is dropped from the variant: the delivery id is not known when the event is built, and the frontend's `WebhookTriggered` handler reads only `type` (it invalidates the `webhooks` and `webhook-logs` queries).

### 5.2 Repository: `infrastructure/postgres/repositories/outbox.rs`

Free functions, `query!` only, private `Row` structs.

| Function | Executor | Behaviour |
|---|---|---|
| `publish(tx: &mut Transaction<'_, Postgres>, event: &SystemEvent) -> Result<PublishedEvent>` | transaction only | Insert the event, then one delivery per `destinations()`; returns the event id and the delivery ids. Taking a `Transaction` stops the type system from ever publishing on the bare pool |
| `load(ex, id) -> Option<StoredEvent>` | any | For the hub |
| `load_since(ex, accounts: &[AccountId], after_id, limit) -> Vec<StoredEvent>` | any | Hub replay after a listener reconnect |
| `claim_due(ex, limit, lease) -> Vec<ClaimedDelivery>` | any | `UPDATE … SET attempts = attempts + 1, available_at = now() + lease WHERE id IN (SELECT id … WHERE status = 'pending' AND available_at <= now() ORDER BY available_at FOR UPDATE SKIP LOCKED LIMIT $1) RETURNING …`, joined to its event |
| `mark_delivered(ex, id)` / `mark_retry(ex, id, available_at, error)` / `mark_failed(ex, id, error)` | any | Status changes |
| `list_webhook_logs(ex, owner, webhook_id, limit, offset)` / `count_webhook_logs(..)` | any | `WebhookTriggered` events of `owner` whose `payload->'payload'->>'id' = webhook_id`, joined to their delivery, newest first |
| `purge(ex, older_than) -> u64` | any | Delete events older than the cutoff that have no `pending` delivery; deliveries cascade |

`infrastructure/postgres/outbox_notifications.rs` wraps a `PgListener` on `outbox` and parses
`<id>:<uuid>` into `(EventId, AccountId)`. A malformed payload is logged and skipped. It mirrors `job_notifications.rs`.

### 5.3 Application

- **Every service mutation** becomes `begin → state write(s) → repositories::outbox::publish → commit`. Services that already hold a transaction publish inside it. The `events` field and `EventBroadcaster` import leave every service.
- `AppServices::with_events` and the test-only constructor without events are replaced by one `AppServices::new(pool, …)`. No build can silently drop events.
- `!briefing now`'s `MorningBriefingSent` moves from `interface/chat/briefing/handler.rs` into a `BriefingService` method (closes a HANDOFF §11 item).
- **`application/outbox/OutboxService`** holds `{ pool }`:
  - `load`, `load_since`, `claim_due` and `purge` for the runtime;
  - `record_delivered(claimed)` and `record_failure(claimed, error)`. Each updates the delivery **and**, when the event is a `WebhookTriggered`, the webhook's `total_delivered_count` / `failure_count` in one transaction. `record_failure` chooses between retry at `now() + domain::webhooks::retry_delay(attempts)` and `failed` when `attempts >= max_attempts`.
- **`WebhookService`**:
  - `enqueue_alert` publishes `WebhookTriggered` in a transaction and returns the delivery id;
  - `list_logs` reads through the new repository functions;
  - `Notify`, `fetch_pending_outbox` and `mark_outbox_*` are deleted.

### 5.4 Runtime: `backend/src/events/`

SQL-free and protocol-free, like `jobs/`; the architecture test enforces both.

```
events/mod.rs         spawn(services, sink, config, shutdown) → JoinHandle; one child CancellationToken
events/listener.rs    one LISTEN per process; reconnect with backoff; fans out to hub and dispatcher
events/hub.rs         SSE hub
events/dispatcher.rs  durable deliveries
events/purge.rs       hourly retention
```

**Listener.** It forwards each `(EventId, AccountId)` to the hub and wakes the dispatcher. On
every (re)connect it tells the hub to replay and wakes the dispatcher once, because a NOTIFY sent
while it was down is gone.

**Hub.**
- The hub keeps `AccountId → Vec<Subscriber>`. Each subscriber has a bounded `mpsc` channel with capacity 64. `subscribe(account)` returns a stream and a guard; the entry is removed when the guard drops.
- On a notification, the hub loads the event through `OutboxService::load` **only if** the account has a local subscriber, then `try_send`s it to each of that account's subscribers. A subscriber whose channel is full is dropped; the browser's `onerror` reconnect and refetch recover it.
- The ownership filter is structural: a subscriber is only ever registered under its own authenticated account.
- **Replay.** The hub records the highest event id it has pushed. On a listener reconnect it calls `load_since(accounts with subscribers, last_seen − 100, 500)`. The window of 100 covers identity ids that commit out of order. Duplicates are harmless: the frontend handlers invalidate caches and nothing more.

**Dispatcher.**
- It is one task. It wakes on the listener, with a 1 s poll as a fallback.
- It claims batches of 20 with a 60 s lease, and loops while a batch is full.
- For each claimed delivery it calls `DeliverySink::deliver`, then `record_delivered` or `record_failure`.
- If a crash lands between the send and the mark, the lease expires and the row is retried. Matrix transaction-id idempotency (below) absorbs the resend within the session.

```rust
#[async_trait]
pub trait DeliverySink: Send + Sync {
    /// False while the channel is down: the dispatcher idles instead of burning attempts.
    fn is_ready(&self) -> bool;
    async fn deliver(&self, delivery: &ClaimedDelivery, event: &SystemEvent) -> Result<(), String>;
}
```

**Matrix sink.** `interface/events/matrix_room.rs` implements `DeliverySink` for `Destination::MatrixRoom`. It keeps
today's checks unchanged, and every error stays retryable, as today:
1. parse the room id;
2. require that the bot is joined;
3. require `is_room_authorized_for_account(owner, room)`;
4. send `text_html(plain_body, html_body)` **with transaction id `outbox-<delivery id>`** via matrix-sdk 0.18's `with_transaction_id`.

Tests use a fake sink. This is the same seam as the jobs `Delivery`, a real external-service boundary with a second implementation.

**Purge.** Every hour it runs `OutboxService::purge(now − 30 days)`. The purge is idempotent, so it takes no advisory lock.

**Composition.**
- `app::run` spawns the events runtime after the API server has started (R35), next to the job runtime, and joins it within the 15 s bounded shutdown.
- `ApiState.broadcaster` becomes `ApiState.hub`.
- `sse_handler` subscribes to the hub and keeps `take_until(shutdown)` and the 15 s keep-alive.

## 6. Contracts

- **OpenAPI:** byte-identical. `WebhookOutboxItem` keeps every field, built from event + delivery:
  - `id` = the delivery id as a decimal string;
  - `webhook_id`, `severity`, `title`, `html_body`, `plain_body` from the payload;
  - `owner_id` = the event account;
  - `room_id` from the destination;
  - `status`, `attempts`, `max_attempts`, `last_error` and `delivered_at` from the delivery;
  - `next_attempt_at` = `available_at`;
  - `created_at` = the event's.
- **Inbound webhook and test-alert responses** (`POST /api/v1/webhooks/{token}` and `POST /api/v1/account/webhooks/{id}/test`): the `outbox_id: String` field now carries the delivery id (`"123"` instead of `outbox_<uuid>`). The type is unchanged and the value was always opaque; the frontend never reads it.
- **SSE:** `{type, payload}` with the same variant names. `WebhookTriggered` gains `title`, `html_body`, `plain_body` and loses `outbox_id`.
- **Chat:** no command or reply changes.

## 8. Error handling and idempotency

- **Mutation.** A publish failure rolls back the state change. The service returns `AppError::Database`, which is an opaque 500.
- **Listener.** A failure is logged; the listener retries after a delay while the dispatcher keeps polling. The cost is SSE latency plus a replay, never lost durable work.
- **Delivery.** It is at least once. Matrix transaction ids absorb a resend within the same session. After `max_attempts` the delivery is `failed`, `failure_count` goes up, and the row stays visible in the logs.
- **Sink not ready** (Matrix disconnected). The dispatcher does not claim, so no attempts are burned. This is a disclosed improvement: the old worker spent attempts while Matrix was down.
- **Hub.** It never blocks a publisher (`try_send`). A load error for one notification is logged and skipped.
- **Shutdown.** The dispatcher stops between deliveries. An in-flight claim is simply left to its lease.

## 9. Testing

- **Domain:**
  - `event_type()` matches the serde tag for every variant;
  - the `Destination` key round-trips;
  - `destinations()` is empty for everything but `WebhookTriggered`;
  - the wire-format test is kept, with the `AccountId` owner.
- **Repository:**
  - `publish` writes the event and its deliveries atomically;
  - a rolled-back transaction leaves no rows and delivers no NOTIFY;
  - a NOTIFY carries `<id>:<uuid>`;
  - two concurrent `claim_due` calls never return the same row;
  - an expired lease is reclaimed;
  - `purge` keeps events with a pending delivery;
  - the webhook log queries are owner-scoped.
- **Service:**
  - each converted mutation writes exactly the expected `event_type` for its owner;
  - a failure forced mid-transaction (the NUL-byte trick) leaves neither the state change nor an event;
  - the `subscribe()` assertions become outbox-row assertions through a `#[cfg(test)]` helper.
- **Hub:**
  - owner isolation (ported from `sse.rs`);
  - an event with no local subscriber is not loaded;
  - replay after a reconnect;
  - a full subscriber is dropped without blocking the others;
  - the SSE stream ends on shutdown.
- **Dispatcher (fake sink):**
  - success leads to `delivered` with the counter updated;
  - a failure leads to a retry at `retry_delay` and then to `failed` at `max_attempts`, with `failure_count` updated;
  - it idles while the sink is not ready;
  - it stops on cancel;
  - the Matrix sink builds transaction id `outbox-<delivery id>` (unit-tested without a homeserver).
- **Contract:** the logs endpoint returns the `WebhookOutboxItem` shape from outbox rows; the inbound webhook returns 202 with a delivery id; zero OpenAPI diff.

## 11. Acceptance

- No `EventBroadcaster`, `tokio::sync::broadcast`, `webhook_outbox`, `spawn_background_workers`, `BackgroundWorkers` or `ModuleContext` remains in `backend/src`.
- Every `SystemEvent` is written by `repositories::outbox::publish` inside the transaction of its state change.
- Killing the process between a webhook alert's acceptance and its delivery: the alert is posted after restart, once per Matrix session.
- A browser receives only its own account's events, on any instance, and recovers after a server listener reconnect.
- `openapi.json` is byte-identical; the full verification list in HANDOFF §5 is green.
